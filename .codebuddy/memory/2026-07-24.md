## fix：工具调用计数清理——for 循环转 while，task-continue nudge 不计入 50 轮限制
- 原 for 循环中 `continue`（max_tokens 恢复、task-continue nudge）会递增 `round` 计数器。当 task-continue nudge 在第 49 轮触发时，耗尽最后一个可用轮次，agent 没有机会在此 nudge 后实际执行工作就直接达上限。
- 修复：for → while 循环，`round++` 放在循环体末尾（工具执行后），只在实际执行工具调用（含正常完成、loop 检测）的轮次递增。`continue`（max_tokens 恢复、task-continue nudge）和 `break`（完成、循环检测、取消）均不递增。
- 两个循环（Anthropic / OpenAI）都改了。
- 清零逻辑：每轮 `streamChat` 调用开始 `round=0`；用户发送新消息触发新的 `streamChat` → 清零。达上限后回复"继续" → 新 `streamChat` → 新 50 轮。
- commit 18c0ddc。

## fix：思考循环检测增强——添加60秒超时上限
- 根因：模型思考陷入重复推理，每次迭代措辞略有不同（"Let me re-read..." vs "Wait, this is interesting..." vs "So maybe the issue is..."），之前 80 字符精确重复检测匹配不上，循环持续到 thinking budget 耗尽才停。
- 修复（`llmStreamService.ts` `callAnthropic`）：
  - 新增 `thinkingStartTime` 计时器，在 `content_block_start` (type: `thinking`) 时设为 `Date.now()`，在文本开始（`text_delta`）或工具调用开始时重置为 0。
  - 每轮 after-loop 检查：`Date.now() - thinkingStartTime > 60s` 且 `!thinkingStuck` → 判定为思考循环，输出 `[思考超时（超过 60s 未产出结果），已自动中断。]`，设置 `thinkingStuck=true` 停止流式读取。
- `MAX_THINKING_MS = 60_000`。思考正常时长通常数秒到十几秒；超过 60 秒纯思考未产出文本/工具，几乎必定是循环。
- commit 66c56ba。
