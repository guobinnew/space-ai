## fix：点击停止按钮无效——isCancelled 传递到流读取循环
- 根因：用户点击「停止」→ `stopGeneration` → `stopSession` → `proc.cancelled=true`，但 `callAnthropic`/`callOpenAI` 的 SSE 流读取循环从未检查 `isCancelled`（也没有使用 `proc.activeStream.signal`），即使 cancelled=true，循环仍持续 reader.read() → 继续在循环输出。
- 修复：`callAnthropic`/`callOpenAI` 新增可选参数 `isCancelled?: () => boolean`，在读取循环检查 `if (done || isCancelled?.()) break`，立即停止读取。从各 loop（含 reactive compact retry 内）传递注入。
- commit 23d4668。

## fix：思考过程出现重复文本块——检测循环内容并自动中断流
- 在 `callAnthropic` 的 SSE 流读取中新增 `thinkingStuck` 检测。当 `block.thinking` 长度 > 320 时，取最后 80 字符与前面 80 字符比较，若相同则判定为思考循环。
- 检测到后：发送 `\n\n[思考出现重复循环，已自动中断。]\n\n` 通知前端；break 内部 line 循环与 while 读取循环，停止继续读取流。思考 block 保留已产生的有效内容，正常返回给外层 agentic loop。
- 与已有前端去重（`chatStore.tsx` 避免显示重复）配合：后者防止显示重复，前者中断耗时流式传输。
- commit 72e28a4。

## fix：agent 陷入无限循环反复输出同样信息
- 根因：agentic loop 无重复检测。agent 反复用相同 name+input 调同一工具（如重复 Read 同一文件、重复 Grep 同一关键词），每轮产出相同结果，循环跑到 MAX_TOOL_ROUNDS(50) 才停，看起来像"无限循环反复输出同样信息"。
- 修复（`llmStreamService.ts` 两个循环）：跟踪 `lastToolSig`（name+JSON(input)）与 `consecutiveRepeat` 计数，连续相同工具调用达 `MAX_CONSECUTIVE_IDENTICAL_TOOLS`(3) 次即中断，输出 `[检测到重复的工具调用…已停止执行以避免无限循环]` 提示。
- `prompts.ts`：强化指令——禁止连续两次以上用相同参数调同一工具，未达预期就换方法。
- commit 1ab8f55。

## fix：上下文使用量计算遗漏缓存 token
- 根因：`callAnthropic` 仅取 `message.usage.input_tokens`（Anthropic 的非缓存输入）。启用 prompt caching 后，system 提示词与早期历史落在 `cache_read_input_tokens`/`cache_creation_input_tokens`，`input_tokens` 只剩新增部分 → 上下文使用量严重偏低，看起来"没算 system/历史"。
- 修复（`llmStreamService.ts` callAnthropic）：`inputTokens = input_tokens + cache_creation_input_tokens + cache_read_input_tokens`，反映完整上下文。
- OpenAI 侧 `prompt_tokens` 已含全部输入，无需改。
- ChatInput 显示：`contextTokens = usage.inputTokens / DEFAULT_CONTEXT_LIMIT(200000)`。`usage` 仅在有 LLM 调用时更新（每轮 message_start），重开会话未发消息时为 null（不显示进度条）。
- commit ef7f8b3。

## fix：用户消息中 [File: path] 回退格式未解析为标签
- 根因：`ChatInput` 在 `filesystemApi.readFile` 失败时发送回退格式 `[File: ${path}]` / `[Directory: ${path}]`（无 `file://` 后缀），但 `refParser.tsx` 的正则只匹配 `[File: path](file://...)` 和 `[File: path (L20-L30)]`，导致回退格式不被解析，原样显示为文本。
- 修复（`refParser.tsx`）：新增 `INLINE_FILE_REF_PLAIN`/`INLINE_DIR_REF_PLAIN` 正则（带负向先行断言 `(?!\()` 避免误匹配 `file://` 格式），解析为 file/dir 标签。
- RefTagList 增强：文件/代码引用标签支持点击在编辑器打开（`useEditorStore.openFile`），加 hover 边框与 title。
- commit b1944f8。

## fix：任务续跑移入 agentic loop 内（彻底解决 nudge 后不继续）
- 前端自动续跑（独立 user 消息 nudge）不可靠：依赖 WS 往返+轮询延迟，且作为独立轮次 agent 易只回文字不调用工具，或被当成新指令。两次反馈"nudge 后不继续"。
- 改造：续跑逻辑移到服务端 `llmStreamService.ts` 的 agentic loop 内。当 agent 无工具调用结束（`toolUses.length===0`）但仍有 in_progress 任务时，在循环内注入 `TASK_CONTINUE_NUDGE` 并 continue（不产生 UI user 消息），最多 3 次（`MAX_TASK_CONTINUE_NUDGES`），超过则结束本轮。复用 max_tokens recovery 模式。
- 新增 `tryGetInProgressTask(sessionId)` 查询 taskService。
- 移除前端 mid-session 自动续跑 effect（`continueTimerRef`/`sendMessageRef`/`wsManager` import），保留打开会话时的「是否继续」询问与手动「继续」按钮。
- 加诊断日志：每轮 `[LLM] round=N tools=[...] stop=... textLen=...`；task-continue nudge 时 `[LLM] task-continue nudge #N`。确认问题后可删。
- commit 376a2d1。
