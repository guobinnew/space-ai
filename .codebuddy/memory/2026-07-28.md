## fix(skills)：修复技能详情页 detail.meta 为 undefined 的崩溃
- 根因：服务端未重启时 `/detail` 端点不存在，请求回退到旧的 `GET /:name` 返回 `{ skill: ... }` 格式，导致 `detail.meta` 为 undefined。
- 修复：`handleSkillClick` 中添加 `data.meta` 存在性检查；渲染条件从 `detail` 改为 `detail && detail.meta`；添加 fallback 机制，当 `/detail` 端点失败时回退到旧的 `/get` 端点并构造兼容的 `SkillFullDetail` 结构。
- 用户需要重启服务端以加载新的 `/detail` 和 `/file` 端点。
- commit cd3843c。

## fix(skills)：修复技能名称含冒号时 404 的问题
- 根因：技能 frontmatter 中的 `name`（如 `ckm:banner-design`）与磁盘目录名不同，`getSkill`/`getSkillDetail` 用 frontmatter name 拼路径导致找不到目录。
- 修复：
  - 服务端 `SkillMeta` 增加 `dirName` 字段记录实际目录名
  - 新增 `findSkillDir` 方法：先尝试直接匹配目录名，再扫描所有目录匹配 frontmatter name
  - `getSkill`/`getSkillDetail`/`getSkillFile` 改用 `findSkillDir` 查找
  - 前端优先使用 `dirName` 调用 API，避免特殊字符导致查找失败
- commit dda5ebe。

## fix(skills)：解码 URL 中的技能名称
- 根因：`segments[2]` 是 URL 编码后的值（如 `ckm%3Adesign`），未解码导致查找失败。
- 修复：在 `handleSkillsApi` 中对 `segments[2]` 调用 `decodeURIComponent`。
- commit 7824f16。

## fix(skills)：兼容新旧两种 detail 响应格式
- 根因：服务端未重启时，`/detail` 端点不存在，请求回退到 `GET /:name` 返回 `{ skill: ... }` 格式，前端检查 `data.meta` 失败。

- 旧格式时构造兼容的 `SkillFullDetail` 结构，文件清单显示 SKILL.md。
- commit 0026af2。
