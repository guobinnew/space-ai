## 文件引用tag源文件存在性检查（commit 2ab45dd）

任务：会话历史消息组件中的文件引用tag，源文件不存在时显示图标标记并禁用点击打开。

实现：
- **服务端** `server/agent/api/filesystem.ts`：新增 `GET /api/filesystem/exists?path=...` 轻量端点。`handleExists` 用 `fs.existsSync` + `fs.statSync`，不读取文件内容，可处理二进制/大文件。返回 `{ exists: boolean, isDirectory: boolean }`。复用 `isAllowedFilesystemPath` 安全检查。
- **客户端** `desktop/src/api/filesystem.ts`：`filesystemApi.exists(path)` 调用上述端点。
- **`desktop/src/components/chat/refParser.tsx`**（核心，被 UserMessage / AssistantMessage 使用）：`RefTagList` 拆出 `RefTag` 子组件，每个 ref 用 `useState<boolean|null>` + `useEffect` 异步检查路径存在性。状态：null=检查中 / true=存在 / false=缺失。缺失时：禁用 `onClick`、显示三角警告 SVG 图标（`--color-error` 色）、降低 opacity、边框变 error 色、tooltip 改为"路径不存在：{path}"。dir 类型本来就不点击，但缺失时同样显示图标。用 `--color-error` 而非 `--color-danger`（后者未定义）。
- **`desktop/src/components/chat/FileRefBlock.tsx`**（独立组件，未在主流程使用，保持一致）：用 `Promise.all` 批量检查所有 ref 的存在性，存入 `existMap`，缺失时禁用点击并显示警告图标。
- **i18n** `desktop/src/i18n/index.ts`：新增 `ref.fileNotFound` / `ref.directoryNotFound` / `ref.notFoundTooltip` / `ref.notFoundHint` 中英文文案。

注意：dev 模式下 Tauri 通过 `bun --hot run sidecar.ts` 启动 agent 服务端，源码改动会自动热重载，无需重新编译 `bun build --compile` 二进制。生产打包时才需 `npm run build:agent`。

清理：剥离了无关的 desktop/package.json、Cargo.lock、tauri.conf.json 等遗留改动，只提交本次任务 5 个文件。

## RefTag prop 重命名修复（commit d723d7e）

报错：`RefTag: 'ref' is not a prop` + `Cannot read properties of undefined (reading 'type')`。

根因：把 prop 命名为 `ref`，React 把它当 ref 转发特殊处理，不会作为普通 props 传入组件，导致组件内 `refItem` 解构得到 undefined。

修复：prop 改名为 `refItem`。React 中 `ref` / `key` 是保留 prop 名，不能作为普通 prop 传递给业务组件。
